# PNQ-003 3.9.165 disabled-runtime hotfix

Release 3.9.165 regressed BustaBuster generated-workflow completion even though
the Umbrel compose did not set `PNQ_V2_RUNTIME_MODE`, so Queue v2 defaulted to
`disabled`. The disabled mode still entered Queue v2 shadow integration points
from the live legacy path: dispatcher shadow enqueue, transport shadow dispatch,
DirectWS auth/result epoch hooks, and ECDSA WS result hooks.

This hotfix restores the pre-Queue DirectWS contract while preserving Queue v2
code and schema for explicit `shadow` mode only.

## Scope

- In `disabled` mode, do not call Queue v2 enqueue, dispatch, auth epoch, result
  recording, or the Queue v2 side-effect runner from legacy hot paths.
- Keep legacy DirectWS send, waiter registration, result ACK, dispatcher result
  handling, and observe-only PNQ telemetry behavior unchanged.
- Preserve Queue v2 shadow behavior when `PNQ_V2_RUNTIME_MODE=shadow`.
- Do not change enforced mode, live cron, device execution, deployment, or schema.

## Gate

- Regression tests prove disabled mode sends exactly once through DirectWS,
  resolves the legacy result path, and makes zero Queue v2 calls.
- Existing shadow-mode tests continue to prove Queue v2 remains detached and
  fail-open when explicitly enabled.
- Focused PNQ/transport/WS tests, build, and diff checks must pass before merge.
